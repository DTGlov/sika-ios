## Locked architectural decisions

- Detail page navigates via `NavigationStack` push (NOT sheet)
- ShareLink with text payload (NOT image generation; web's `/monthly-share/{id}/opengraph-image` not yet ported)
- Direct Supabase access for all CRUD (read + dismiss + view + share tracking)
- Banner trigger condition matches web exactly: `viewed_at IS NULL AND dismissed_at IS NULL AND generated_at >= now − 30d`
- Two card types render differently: headline (centered, 24pt) vs all others (left-icon, 16pt)
- View tracking fires once on first appear (matches web's `viewedRef`)
- Banner X dismisses ONLY this recap_id; future cycles' rows generate fresh
- `MonthlyAccent` is a SEPARATE enum from `InsightAccent` (same shape, kept distinct for type safety and future divergence)
- `InsightStat` IS reused (same shape on web; no need to duplicate for `MonthlyCard.stat`)
- `MonthlyCardSymbol` and `InsightSymbol` are SEPARATE utilities (per the prompt's preference for type safety; trivial duplication)

## Behavioral notes

- **First sign-in**: parallel batch resolves; if today's row matches the trigger predicate, banner appears between DailyInsight and CycleCard.
- **Banner body tap**: pushes detail; on first appear, marks `viewed_at` (clears banner permanently for this recap).
- **Banner X tap**: optimistic local clear + fires `dismiss` UPDATE (sets `dismissed_at`). No navigation.
- **Detail page**: 5–7 cards stagger in (each 0.08s after previous). Tapping Share opens iOS share sheet with the text payload. The `onShare` callback fires immediately on tap (ShareLink doesn't expose a success callback) — matches web's "fire shared_at after user taps" approximation.
- **Navigating back**: `navigatedRecap` resets to nil; if `viewed_at` was set, banner doesn't reappear.
- **Cross-platform**: dismissing on iOS persists to web instantly via Supabase (assuming `dismissed_at` column exists — see below).

## Out of scope (deferred)

- **`dismissed_at` column existence** — web's `MonthlyRecap` TS type doesn't include it. iOS issues an UPDATE that may silently fail if the column doesn't exist on the table. The optimistic local clear still gives correct session UX. If the column is genuinely missing, follow-up: either add the column server-side (and update web's TS type) or strip the dismiss path on iOS.
- **Image-based share output** — web's share path tries `${origin}/monthly-share/{id}/opengraph-image` first; iOS ships text-only. Image port deferred.
- **`/monthly` deep linking from push notifications** — push system doesn't exist yet
- **PostHog or other analytics events** on view/share — Phase 5b only does DB UPDATEs
- **Multi-recap history view** — only "latest" matters
- **Pull-to-refresh on detail view** — Home's pull-to-refresh covers it
- **Edit/regenerate buttons** — not exposed on web either
