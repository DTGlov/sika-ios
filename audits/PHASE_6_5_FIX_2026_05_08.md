## Locked architectural decisions

- Single Supabase fetch + in-memory aggregation. No multiple parallel queries.
- Aggregate is a PURE function, separated from the fetch path — unit-testable without network.
- NavigationStack push (matches Phase 5b/5c pattern).
- Past-cycle navigation NOT shipped on the detail page itself. Home's existing chevron pair is the cycle navigator; whichever cycle is "current" on Home is the one passed to detail.
- Bar fill: hardcoded rose `#F43F5E` at 60% opacity. NOT category color, bucket color, or theme color — uniform "spent" treatment.
- Top spending capped at 5; income uncapped.
- Income grouping: `category.name ?? note ?? "Other"` (3-tier fallback).
- Spending grouping: `category.name ?? "Uncategorized"` (2-tier; deliberately no note fallback — web's logic).
- Spending excludes `paid_from_goal_id` transactions (sinking-fund double-count avoidance; matches Phase 3's SpendCalculator fix).
- No row taps; read-only.
- No entrance animations beyond the loading-state replacement; no count-up.
- Single muted line for empty state (no illustration, no dedicated empty-state component).

## Adaptations from the prompt's templates

The prompt's spec assumed several things that didn't match the iOS codebase:

1. **`BudgetCycle` type** → iOS uses `Cycle` (already `Equatable, Hashable`); no rename needed.
2. **Supabase select with joins** (`category:categories(*, bucket:budget_buckets(*))`) → iOS Transaction model has no nested category/account fields. Replaced with: fetch transactions only, look up category names via a `[UUID: TransactionCategory]` dict supplied by the caller. AppState already holds `categories: [TransactionCategory]`, so the view passes them through to the service. No second round-trip.
3. **`actor CycleDetailService { static let shared = ... }`** → `final class` + `SupabaseManager.shared.client` (matches existing iOS service pattern from Phases 2–7).
4. **`appState.currentUserId`** → not needed; RLS scopes the fetch to the current user via session cookies.
5. **`@EnvironmentObject var appState: AppState`** → `@Environment(AppState.self) private var appState` (Observable, not ObservableObject).
6. **`CurrencyFormatter.standard`** → existing iOS API is `CurrencyFormatter.format(_:code:)` which already produces full precision ("GHS 1,234.56" with thousands separator + 2 decimals). Used that throughout — no `.standard` variant needed.
7. **`Color(red:green:blue:)` literal RGB** → iOS already has `Color(hex:)` extension on SikaTheme; used `Color(hex: 0xF43F5E)` and `Color(hex: 0xD4A017)` for the brand rose and gold.
8. **`SikaTheme.Color.mutedForeground.opacity(0.2)` for borders** → existing `SikaTheme.Color.border` token is the right semantic; used that.

## Behavioral notes

- **Tap CycleCard on Home** → optimistic state update sets `navigatedCycle`; NavigationStack pushes detail.
- **Detail loads** → skeleton renders for ~100-300ms, then full summary appears (no fade).
- **`.task(id: cycleStartString)`** → re-runs fetch only when navigating to a different cycle (rare with the current Home flow, but future-proof if past-cycle direct navigation ships).
- **Settings preview** still uses CycleCard without `onTap` (no tap target on the preview).
- **No rollback on fetch failure** — shows muted "Could not load cycle details. Try again." line. User can navigate back and retry.
- **Spending excludes paid-from-goal** — matches Phase 3's correct cycleSpent semantics; users with sinking funds see the same numbers on Home and detail page.
