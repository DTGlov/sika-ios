### Service
- `Services/IncomeService.swift` — extended the S1/onboarding service with:
  - `IncomeSourcePayload` struct (full edit surface: includes `icon` +
    `account_id` which the onboarding `IncomeSourceDraft` omits)
  - `create(payload:)` — insert + select().single() → `IncomeSource`

  - `delete(id:)` — hard delete (matches web exactly)
  - `syncMonthlyIncome(userId:sources:)` — sums active sources via
    `monthlyEquivalent`, writes the total to `profiles.monthly_income`. The
    load-bearing side effect — Phase 9's HealthRow reads
    `profile.monthlyIncome`, so this MUST run after every mutation.
  - `static monthlyEquivalent(amount:frequency:)` — convenience wrapper
    around `IncomeFrequency.monthlyMultiplier`. Constants come from the
    enum (4.333 weekly, 2.167 biweekly) which are already pinned to web's
    `lib/income.ts` to the digit.

### State (`AppState`)
Added in a "Phase S2 — Settings → Income Sources" section after S1's
`deleteAccount()`:
- `createIncomeSource(name:amount:frequency:expectedDay:icon:accountId:isActive:)`
- `updateIncomeSource(id:name:amount:frequency:expectedDay:icon:accountId:isActive:)`
- `deleteIncomeSource(_:)`
- Private `syncLocalProfileMonthlyIncome()` — recomputes total from the
  current `incomeSources` array and stamps the result onto the in-flow
  `Profile.monthlyIncome` so the UI (HealthRow + Total Income echo card)
  reflects the change without a profile refetch.

Each mutation method does all four steps in order:
1. Mutate `income_sources` on Supabase (CRUD)
2. Update the local `incomeSources` array (append / replace / remove)
3. Call `incomeService.syncMonthlyIncome(...)` — writes `profiles.monthly_income`
4. Call `syncLocalProfileMonthlyIncome()` — refreshes the local profile cache

Skipping step 3 breaks Phase 9's HealthRow on the next session. Skipping
step 4 means the UI shows stale total until the next profile refetch.

## Locked architectural decisions

- **Hard delete, NOT soft archive.** Matches web exactly.
- **SwiftUI Alert confirmation before delete.** iOS adds for safety; web
  has no confirm (locked: idiomatic divergence).
- **`syncMonthlyIncome` MUST fire after every mutation** (create, update,
  delete). Not optional. Phase 9's HealthRow depends on it.
- **Monthly equivalent constants: 4.333 (weekly), 2.167 (biweekly).**
  Pinned to web's `lib/income.ts` via `IncomeFrequency.monthlyMultiplier`.
- **`≈ {monthlyEq}/mo` line shows only for weekly + biweekly.** Monthly
  and irregular skip it (the rendered amount IS the monthly figure for
  monthly, and irregular has no defensible monthly equivalent).
- **Quick-add templates pre-fill the form** (iOS-only fix-on-way for
  web's `void template;` no-op).
- **Form sheet is a bottom sheet (`.presentationDetents([.large])`)** on
  iOS, NOT a centered Dialog like web.
- **AlertCircle warning inline** when fixed-frequency source has null
  `expected_day`. Yellow #FBBF24 + `exclamationmark.triangle.fill`. Tap
  opens edit form.
- **Active toggle in edit mode only.** Defaults to true on create. (No
  hidden state surface during the very first save.)
- **NO mutation hooks.** Configuration paths don't tick points / streaks /
  badges — same rule S1 locked.

## Adaptations from the prompt's blueprint

1. **`amount: Decimal`, not `Double`** — S1 / Phase 9 / T1 precedent is
   Decimal for all currency values on iOS. The prompt's Double signature
   was kept consistent with web JS but iOS converted at the boundary.
2. **Existing `IncomeService`, not new `IncomeSourceService`** — S1 + the
   onboarding flow already use `IncomeService` as the singleton-shaped
   `final class`. Renaming would have required threading a second service
   through 7 AppState init sites. CRUD methods bolted onto the existing
   class instead.
3. **`SupabaseManager.shared.client`** — iOS pattern is the wrapping
   manager, not `SupabaseClient.shared` (the prompt was wrong here, same
   as S1's `currentSession?.accessToken` correction).
4. **Profile field is `Decimal?`, not `Double`** — `withMonthlyIncome(_:)`
   takes `Decimal?` and delegates to the existing private `copy(...)`
   helper.
5. **No separate `IncomeSourceService`** — `IncomeSourcePayload` lives as
   a nested struct on `IncomeService` to mirror `AccountService.AccountInsert`
   precedent.
6. **`incomeSources` is `private(set)` on AppState** — the three new
   mutation methods are the only write sites; the array stays
   read-only from views.
7. **Day-of-month uses a private 1-31 stepper, not the Recurring tab's
   1-28-or-LastDay picker** — income sources don't have the "last day of
   month" semantics that recurring transactions need (paychecks land on
   the 28th or 31st, never "last day"). Built a local
   `DayOfMonthStepperView` inside the form sheet.
8. **Day-of-week reuses Recurring's `DayOfWeekPickerView`** — same shape
   (0=Sun..6=Sat).
9. **12 emoji set chosen ad-hoc** — audit Section 5.2.2 with the
   IncomeSource-specific emoji list didn't ship in the iOS repo
   (web-only). Chose 12 income-flavored emojis (💰💼🎁💻📈🏦💵💳🪙📊🧾🤝)
   that don't collide visually with the goal/recurring set.

## Behavioral notes

- **Create**: `isActive` is forced to `true` on the AppState call site —
  the toggle is hidden in the form's create mode.
- **Edit**: form is pre-filled from `editingSource` on `.onAppear`. The
  Active toggle is shown so users can pause a source without deleting
  it. Paused sources are filtered out of `syncMonthlyIncome`'s active
  set, so the aggregate updates immediately on Save.
- **Delete**: tap trash → Alert → confirm → `appState.deleteIncomeSource(id)`
  fires CRUD + syncMonthlyIncome + local cache refresh. Toast shows
  "Income source deleted" on success, "Failed to delete" on error.
- **Quick-add template**: pre-fills name (template label), emoji,
  frequency, and suggested expected_day. User can override any field
  before saving. After save, the strip remains visible — fresh template
  taps open a new form (templates are reusable).
- **AlertCircle**: visible only when frequency is monthly/weekly/biweekly
  AND `expected_day` is nil. Tapping the warning routes through the
  same `editingSource = source` binding the pencil icon uses.
