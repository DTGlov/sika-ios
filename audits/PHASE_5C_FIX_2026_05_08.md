## Locked architectural decisions

- Story cards are **PASSIVE** — no tap target (matches web v1 explicitly; sourceURL captured for forward-compat with v2)
- Direct Supabase access for read + markRead (no HTTP routes)
- Per-digest read tracking (one row in `user_daily_reads` covers all 4 stories)
- Idempotent insert (silently swallow 23505 unique violation if it occurs)
- Auto-read uses `.task { Task.sleep }` — not `Timer` or `DispatchQueue`. View-lifecycle bound; cancels on disappear
- Banner tap navigates via NavigationStack push (consistency with Phase 5b)
- Cross-platform: marking read on iOS persists to web instantly (and vice versa)

## Behavioral notes

- **First sign-in**: parallel fetch loads today's digest + read state. If digest exists and unread → banner shows.
- **Banner tap**: pushes detail view via NavigationStack.
- **On detail appear**: 10-second timer starts via `.task`. Manual "Mark as read" button also fires the same path early.
- **Either path**: optimistic `digestRead = true` (with `withAnimation`) → banner clears on Home, button switches to "✓ Read" → idempotent insert into `user_daily_reads` runs in background.
- **View disappear before 10s**: `Task.sleep` cancels (raises `CancellationError`); `try?` swallows it; no read recorded. Matches web's `clearTimeout` cleanup.
- **No-digest case**: cron hasn't run for today (or skipped); `fetchTodayDigest` returns nil; banner doesn't show; no error.
- **Story card tap**: nothing happens. Web v1 does not ship story tap; iOS matches.
