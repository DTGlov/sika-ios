## Locked architectural decisions

- 7 themes, default fallback to `.sankofa` for unknown rawValues (matches DB NOT NULL DEFAULT 'sankofa')
- Solid background per theme (no gradients in palette; existing CycleCard's subtle radial gradient overlay preserved for depth)
- Motifs are **stylized Canvas approximations**, not verbatim SVG ports. The existing SankofaMotif explicitly took this path; the 6 new motifs match the style. Faithful enough to be recognizable; not pixel-perfect.
- Tap-to-commit picker (no Save button) — picker dismisses on selection
- Profile fields are `let`; optimistic mutation goes through `Profile.withCardTheme(_:)` copy-construction
- Direct Supabase UPDATE for `profiles.card_theme` (no API route)
- Optimistic local update + rollback on error (matches web's pattern)
- Picker uses `NavigationStack` + `.presentationDetents([.medium, .large])`
- 2-column `LazyVGrid` with 12pt spacing between mini cards
- Mini cards render motifs at half size; chrome reduced to SIKA wordmark + theme name only
- `.sensoryFeedback(.selection, trigger: currentTheme)` on picker — iOS-native haptic polish that web doesn't have
- `withAnimation` wraps mutations in AppState (avoids iOS 26 SDK Task-init ambiguity from Phase 5a/5b/5c)
- CycleCard tap on Home: NO-OP (Phase 6.5 will wire to Cycle Details when that ships)

## Adaptations from the prompt's templates

The prompt's spec assumed several things that didn't match the existing codebase:

1. **`CycleCardTheme` as a new enum** → reused existing `HeritageCardTheme` from Phase 1 (already had all 7 themes + full palette config matching web verbatim)
2. **`HeritageThemeConfig` / `HeritageThemePalette` separate types** → existing `HeritagePalette` struct already in `HeritageCardTheme.swift`; extended the enum with `subtitleLine`, `pickerOrder`, `balanceColor(forNet:)` methods directly
3. **`Profile.cardTheme: String?`** → actual model has `cardTheme: String` (NOT NULL). No fallback needed when reading from `profile.cardTheme`; only when mapping to enum (via `HeritageCardTheme(rawValue:) ?? .sankofa`)
4. **`SupabaseClient.shared.client` template** → actual is `SupabaseManager.shared.client` (matches existing service pattern from Phases 2/3/4/5/7)
5. **`@MainActor` on AppState methods** → AppState is already `@MainActor @Observable final class`; redundant per-method annotation omitted
6. **`@EnvironmentObject` on CardStyleSection** → AppState uses `@Observable`, not `ObservableObject`; switched to `@Environment(AppState.self)`
7. **`appState.profile?.fullName`** → profile lives on `flow: AuthFlow.authenticated(profile:)`, not as a top-level property. Pattern-matched via `if case .authenticated(let profile) = appState.flow`
8. **Verbatim SVG path data ports** → kept stylized Canvas approximations (existing SankofaMotif already took this path; the prompt's "fallback if too complex" guidance applies to all 6 new motifs)
9. **CycleCardSurface as a new sub-view** → existing CycleCard already has the right structure; added 6 motif cases to its dispatcher rather than refactoring chrome out
10. **EMVChip as a new component** → existing `EMVChip` already exists with `primary`/`secondary` parameters; reused as-is
11. **24pt corner radius and 1.586 aspect ratio** preserved from Phase 1 (prompt suggested 20pt and 85.6/54=1.585; close enough that no visual change is justified)

## Behavioral notes

- **First sign-in**: AppState reads `flow.profile.cardTheme`. If string is in the enum's known cases, that theme renders; else `.sankofa` fallback.
- **Settings → Card Style → Change card**: sheet opens with current theme highlighted. Tap any theme → optimistic update fires, sheet dismisses, Home + Settings preview both update via the @Observable AppState.
- **Network failure on update**: rollback to previous value (also wrapped in `withAnimation`). User sees the new theme briefly then it reverts.
- **Cross-platform**: Web and iOS share the same `profiles.card_theme` column; changing on one persists immediately to the other.
- **Hint card persistence**: `HintCard.cardThemeAvailable` dismissal persists via the existing `dismissed_hints` infrastructure (Phase 4).
