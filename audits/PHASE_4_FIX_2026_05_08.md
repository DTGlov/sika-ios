## Locked architectural decisions

- **HintId is STRUCT, not enum.** Web's union has a `sunday_recap_${year}_W${week}` template-literal arm that can't be expressed as a Swift enum case.
- **dismissedHints is `Set<String>`** at AppState level (web uses `string[]` with `.includes()`; Set gives O(1) `contains`).
- **Optimistic dismiss with NO rollback.** Network failures are silently logged in DEBUG and ignored otherwise.
- **`hintsLoaded` flag** prevents flash-then-hide on first paint. Without it, HintCards would render briefly then disappear when data arrives.
- **SundayRecapCard does NOT share chrome with HintCard.** Border opacities differ (20% vs 30%) and the layout is structurally distinct.
- **`resetHints` exists in AppState but no UI consumer in this PR.** Settings rebuild will wire it later.
- **Phase 4 ships only 2 HintCard consumers + SundayRecapCard.** Other hints (recurring_intro, accounts_intro, etc.) ship when their respective pages rebuild.

## Adaptations from the prompt's templates

The prompt's templates assumed a service pattern that doesn't match the existing iOS codebase. Changes made to align:

- `actor DismissedHintService { static let shared = ... }` → `final class DismissedHintService { private var client: SupabaseClient { SupabaseManager.shared.client } }`. Default no-arg init, injected via AppState's existing service-injection convention.
- `@Published var dismissedHints` → `private(set) var dismissedHints` (AppState uses `@Observable`, not `ObservableObject` + `@Published`).
- `appState.currentUserId` → `appState.session?.user.id` (no `currentUserId` property exists; user UUID is on `session.user.id`, matches the existing pattern at `loadProfile` line 352).
- `let body: String` parameter on HintCard → `let message: String`. The `body` name would collide with SwiftUI's `var body: some View` requirement.
- `.not("goal_id", operator: .is, value: "null")` → fetch-then-filter client-side. Avoids portability issues with the Supabase Swift SDK's null-filter syntax. Week's transfer volume is small (<50 rows typical).
- For `resetAll()`'s DELETE, added `.neq("hint_id", value: "")` filter because PostgREST refuses unfiltered DELETE. RLS still scopes to the user so the filter is a tautology that satisfies PostgREST safety.

## Behavioral notes

- **First sign-in**: `hintsLoaded` flips true after the parallel fetch resolves. Skeleton placeholder visible briefly (a gray rounded card), then real content or `EmptyView` if dismissed.
- **On Sundays (today is 2026-05-08, Friday)**: `SundayRecapCard` renders nothing — the `weekday == 1` guard short-circuits before any fetch. To verify Sunday rendering, set the device clock to a Sunday.
- **On non-Sundays**: `SundayRecapCard` renders `EmptyView()` — no skeleton, no fetch, no spacer.
- **Dismissing a HintCard**: card slides up + fades out, dismissed_hints upsert fires in background, won't show again until Settings reset (future).
- **Dismissing SundayRecapCard**: same animation, dismiss is keyed to the current ISO week. Next Sunday a new ISO-week id rotates in and the card returns automatically.
