# Phase 9.5d — Animated cowrie splash + adaptive duration — 2026-05-12

Implementer: Claude Code
Predecessor: `chore/app-icon-cowrie` (icon PNG generator, same primitives)

This phase ships the first-impression moment when launching Sika: a
two-layer splash with a static cowrie on navy during the OS-controlled
launch phase, handed off seamlessly to a SwiftUI Canvas animation that
assembles spine + ribs onto the body before cross-fading into Home.

## What Shipped

### Launch storyboard layer (Info.plist `UILaunchScreen`)
The project uses the modern iOS 14+ `UILaunchScreen` dictionary
approach (no `.storyboard` file). The launch screen is now configured
with two named-asset references:

- `UIColorName` → `LaunchBackground` (named color in Assets)
- `UIImageName` → `LaunchCowrie` (named imageset, 3 scales)

This produces a navy full-bleed background with the cowrie centered
at 280pt — visually identical to the SwiftUI splash's frame-0 state,
so the storyboard → SwiftUI handoff has no jump or flash.

### Assets (Assets.xcassets/)
- `LaunchBackground.colorset/` — universal sRGB color, #0E1A2E (navy).
- `LaunchCowrie.imageset/` — transparent-background cowrie at three
  scales (no inner background; the `UIColorName` provides the navy
  fill):
  - `LaunchCowrie.png` (280×280, @1x)
  - `LaunchCowrie@2x.png` (560×560, @2x)
  - `LaunchCowrie@3x.png` (840×840, @3x)
- `scripts/export-launch-cowrie.swift` — generates all three scales
  in one CG pass. Sibling of `scripts/export-app-icon.swift`; re-run
  after any SikaMark geometry tweak.

### App
- `App/SplashCoordinator.swift` (new) — `@Observable @MainActor`
  coordinator. `isShowing: Bool` drives mount/unmount of the overlay
  and the root content's scale/fade. `mode: SplashMode` pinned at
  init via `detectMode()` reading a `UserDefaults` timestamp; a
  re-open within 600s is `.warm`, otherwise `.cold`. DEBUG-only
  `replayAsCold()` forces a fresh cold-assemble for dev review.
- `App/SikaApp.swift` — wraps the existing `RootView()` in a
  `ZStack` with the splash overlay above it. Root content gets
  `.scaleEffect(splash.isShowing ? 0.95 : 1.0)`,
  `.opacity(splash.isShowing ? 0 : 1)`, and a 300ms `.easeOut`
  animation so it scales-in-with-fade as the splash scales-up-with-
  fade-out. New `splashCoordinator` injected via `.environment(...)`.

### View
- `Features/Splash/AnimatedSplashView.swift` (new) — SwiftUI `Canvas`
  drawing the same cowrie primitives as `SikaMark` (ellipse body +
  spine line + 4 V-pair ribs) but with per-element progress state.
  Body is fully visible at frame 0 — only spine and ribs animate, so
  the storyboard cowrie stays visually anchored across the handoff.

### Settings (DEBUG-only)
- `Features/Settings/SettingsView.swift` — picks up
  `@Environment(SplashCoordinator.self)` and renders a
  `#if DEBUG` "[DEV] Replay splash" button at the bottom of the
  scroll. Tap dismisses Settings and calls `replayAsCold()` so the
  splash re-mounts at the app root.

## Timeline (cold launch, ~1.6s)

| t        | Event                                            |
|----------|--------------------------------------------------|
| 0        | Body visible (matches storyboard handoff)        |
| 0–200    | Body-only hold                                   |
| 200–600  | Spine draws top-to-bottom (`easeInOut`, 400ms)   |
| 600–1100 | 4 ribs staggered out (100ms apart, 200ms each)   |
| 1100–1300| Full-cowrie hold                                 |
| 1300–1600| Exit: scale 1→1.05 + fade 1→0 (`easeIn`, 300ms) |

Concurrent with the exit transition, root content scales `0.95 → 1.0`
+ fades `0 → 1` over 300ms — the cross-fade.

## Timeline (warm relaunch, ~700ms)

| t       | Event                                              |
|---------|----------------------------------------------------|
| 0       | Body visible                                       |
| 0–100   | Body-only hold                                     |
| 100–300 | Spine + 4 ribs appear together (`easeOut`, 200ms)  |
| 300–400 | Full-cowrie hold                                   |
| 400–700 | Exit transition                                    |

## Locked architectural decisions

- **Two-layer splash** — Info.plist `UILaunchScreen` (mandatory) +
  SwiftUI `AnimatedSplashView` overlay. Same cowrie, same size, same
  position, same navy across both layers.
- **Body always visible at frame 0** — the spec was corrected here.
  If the body faded in, the user would see storyboard cowrie →
  cowrie vanishes → cowrie fades back in. Keeping the body opaque
  from frame 0 means only the spine + ribs assemble.
- **Adaptive duration via 10-minute warm window** — `UserDefaults`
  timestamp on each launch; `now - last < 600s` → `.warm`. No
  fancy session bookkeeping; the timestamp is stamped fresh on each
  init so consecutive re-opens within the window stay warm.
- **No background → foreground splash** — iOS treats backgrounding
  separately from launching. A `SikaApp.init` only runs on process
  death + relaunch, so the splash naturally fires only on real
  launches.
- **No sound effects** — silent default.
- **Exit cross-fade** — splash scales `1 → 1.05` while root content
  scales `0.95 → 1.0`. Both fade. 300ms `easeIn` / `easeOut`.
- **Splash mounts at SikaApp root**, above `RootView`. The root's
  existing `NavigationStack` is left alone.
- **SikaMark untouched** — the splash redraws the same primitives in
  its own Canvas. The original `SikaMark.swift` is unchanged.

## Adaptations from the prompt's blueprint

1. **No `.storyboard` file authored** — the project already uses the
   iOS 14+ `UILaunchScreen` dict in Info.plist. Two named-asset
   references (`UIColorName` + `UIImageName`) are equivalent to the
   "navy background + centered UIImageView" the prompt described and
   avoid editing Xcode interface-builder XML.
2. **`@Observable @MainActor`, not `ObservableObject`** — iOS pattern.
   AppState / ToastManager use the same shape; SplashCoordinator
   follows. Environment injection via `@Environment(...self)`, not
   `@EnvironmentObject`.
3. **`Task.sleep(for:)`, not `DispatchQueue.main.asyncAfter`** —
   structured concurrency reads cleaner for the sequential timeline
   and runs naturally inside `@MainActor`.
4. **Launch image at @1x/@2x/@3x with transparent background** — the
   `UIColorName` provides the navy fill, so the image only needs to
   contain the cowrie shape. Three scales emitted at 280 / 560 / 840
   pixels match the SwiftUI splash's 280pt display size exactly so
   the handoff is pixel-aligned on all devices.
5. **No "skipped" mode at runtime** — `detectMode()` only emits
   `.cold` or `.warm`. The `.skipped` case stays in the enum as a
   placeholder for future background-trigger gating; the early-out
   in `playAnimation()` is kept defensively.

## Acceptance (real device)

Real-device test plan in the PR body — 20 steps covering cold launch,
warm relaunch, background return (no splash), and a long-pause cold
relaunch. Visual checks for the storyboard → SwiftUI handoff
(no jump), spine top-to-bottom draw, rib staggering, and exit
cross-fade.

The DEBUG "[DEV] Replay splash" button in Settings lets the operator
exercise the cold assemble without killing the app between iterations.

## Out of scope

- "Cowrie flies to TopBar" exit pattern — considered, rejected in
  favor of scale-and-fade for this PR; the TopBar version remains a
  future option without breaking changes.
- Sound effects.
- First-launch-only "super cinematic" mode — rejected in favor of
  every-launch adaptive duration.
- Per-theme color variations (dark/tinted) of the launch screen.
- Splash analytics (impressions / time-to-interactive).
