## Locked architectural decisions

- Two distinct components (NOT shared chrome with HintCard or each other)
- IncomeNudge and PendingRecurring are in-memory wrappers, NOT tables
- Income nudge dismissal: per-(user, source, due_date), 3 actions metadata, all suppress equally
- Recurring "handled" tracking: bumping `recurring_transactions.last_generated_date` forward (no separate table)
- "Show only the latest missed due date" — multiple missed occurrences collapse to one card; Confirm inserts ONE transaction; older missed dates silently bumped
- Income-typed recurring rules filtered from visible pending (legacy data hygiene)
- Generation runs ONCE per session via `hasGeneratedThisSession` flag (mirror web's useRef)
- All "today" comparisons use device-local time
- Confirm/Log paths do NOT open the wizard (direct insert)
- "Yes, log it" requires a default account (`account.isDefault == true`, fallback first account); silent no-op when no account exists (toast UI not shipped)

## Adaptations from the prompt's templates

Same as Phases 4/5a:
- `actor` services → `final class` + `SupabaseManager.shared.client`
- `currentUserId` → `session?.user.id`
- `accounts.first(where: { $0.isDefault })` → `$0.isDefault == true` (Account.isDefault is `Bool?` optional)
- `SikaTheme.Color.amberAccent` (didn't exist) → `SikaTheme.Color.sikaWarning` (already exists at the same hex `#FBBF24`)
- `.in("col", value: ids)` → `.in("col", values: ids)` (Supabase Swift SDK uses the plural keyword)
- `withAnimation { Task { await ... } }` at view callsite → moved into AppState mutations to avoid iOS 26 SDK Task-init ambiguity (Phase 5a precedent)
- Async-let ternary fan-out for nudges + recurring → simpler sequential phase-2 loader (`loadNudgesAndRecurring`) after the parallel batch. The dependency on `incomeSources` and the once-per-session guard make the simple sequence clearer than fighting `async let`.
- Income nudge log uses existing `TransactionService.insert(draft)` rather than an inline Supabase insert — keeps the insert path consistent with the wizard.

## Behavioral notes

- **First sign-in**: parallel batch resolves; phase-2 loader runs (income nudges fetched, recurring auto-log silent generation pass + pending collection); flow flips to `.authenticated`. Total round-trips: parallel-batch + 2 sequential.
- **Pull-to-refresh**: re-fetches everything in the parallel batch + re-fetches income nudges. Pending recurring is NOT regenerated (once-per-session guard prevents duplicate auto-log inserts).
- **Income nudge "Yes, log it"**: inserts an income transaction via `TransactionService` (same path as wizard) using the user's default account. Records `.logged` dismissal. Card slides out. `refreshHomeData` is called so the new transaction appears in stats.
- **Income nudge "Not yet"**: card slides out, `.snoozed` recorded. No transaction.
- **Income nudge X**: card slides out, `.dismissed` recorded. No transaction.
- **Pending recurring "Log it"**: inserts a transaction at the latest missed date and bumps `last_generated_date`. Older missed dates are silently passed over (their insertion is the responsibility of the next session's auto-log pass or the user's manual Add flow).
- **Pending recurring "Skip"**: just bumps `last_generated_date`. No transaction.
- **Auto-log silent generation**: on first session load, `auto_log=true` rules get one transaction per missed occurrence inserted, then `last_generated_date` bumped to the latest. Re-launching the app within the session won't re-generate.
- **Income-typed recurring rules**: never appear on Home (filtered in `visiblePendingRecurring`).
- **Cross-platform consistency**: web and iOS share the same `recurring_transactions.last_generated_date` and `income_nudge_dismissals` tables — dismissing on one platform persists immediately to the other.
