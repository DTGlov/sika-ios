# Phase 3 Fix — Savings Bucket Math + WeeklyChart — 2026-05-07

Implementer: Claude Code
Source-of-truth audit: `/audits/SAVINGS_BUCKET_AND_WEEKLY_CHART_2026_05_07.md` (web)
Inspection audit: `/audits/TRANSACTION_MODEL_INSPECTION_2026_05_07.md` (iOS)

## Problem Solved

1. **Savings bucket showed 0 on iOS where web showed real values.** Web counts goal contributions and inbound savings/investment account transfers; iOS only counted expense-categorized savings transactions.
2. **`cycleSpent` over-counted** because iOS used a no-op `goalId == nil` filter where it should have used `paidFromGoalId == nil`. Since the pipeline already filters `type == .expense` first, no expense row ever has `goalId` set, so the filter excluded nothing — paid-from-goal expenses were silently included in cycle spend.
3. **No WeeklyChart on Home.** Deferred from Phase 2 because it requires the Apple Charts framework's first introduction in iOS Sika.

## Changes

### Model
- `Transaction.paidFromGoalId: UUID?` added with CodingKey `paid_from_goal_id`. Was previously silently dropped on decode (no field in the model, no entry in `CodingKeys`).
- Doc comments on `goalId` and `paidFromGoalId` clarify the two-field distinction (`goal_id` is set on TRANSFERS contributing TO a goal; `paid_from_goal_id` is set on EXPENSES paid FROM a goal's saved funds).
- `AccountType.savingsLike: Set<AccountType> = [.savings, .investment]` static added — mirrors web's `SAVINGS_ACCOUNT_TYPES`.
- `AddTransactionWizardViewModel.swift` Transaction memberwise init updated with `paidFromGoalId: nil` (the wizard doesn't yet support paid-from-goal expenses; that's a future "Spend from target" feature).

### Calculator fixes
- `SpendCalculator.cycleSpent`: filter changed from `goalId == nil` to `paidFromGoalId == nil`. Doc comment rewritten to accurately describe the behavior and reference web's `totalSpentActual` (use-dashboard-data.ts:101).
- `BucketSpendCalculator.compute()`:
  - takes `accounts: [Account]` (new parameter, between `budgetBuckets` and `cycle`)
  - filter on the expense pass changed from `goalId == nil` to `paidFromGoalId == nil`
  - second pass added for cycle transfers, mirroring web's use-dashboard-data.ts:134-156:
    - **Rule 1**: `tx.goalId != nil` → savings (regardless of account types). Mutually exclusive with Rule 2 via `continue`.
    - **Rule 2**: destination is savings-like AND source is NOT savings-like → savings. Internal savings shuffles (savings → savings, investment → investment) are skipped because no new money entered the savings sphere.

### New component
- `Sika/Features/Home/Components/WeeklyChart.swift` — first `import Charts` callsite in the iOS codebase.
  - 7 daily bars, oldest-first, gold tint (`SikaTheme.Color.sikaAccent`)
  - Cycle-aware "now" anchor: `min(today, cycle.end)` on current cycle, `cycle.end` on past cycles
  - Spend semantics: expense AND `paidFromGoalId == nil` (matches `bucketExpenses`)
  - X-axis: month-abbrev + day labels in `SikaTheme.Typography.sans(10)` mutedForeground
  - Y-axis: hidden (matches web)
  - Empty days: pre-seeded to zero so the chart always renders 7 entries

### Wiring
- `AuthenticatedHomeView.swift`:
  - `BucketStrip` callsite passes `accounts: appState.accounts`
  - `WeeklyChart` inserted between `BucketStrip` and `RecentTransactionsWidget`

## Behavioral deltas users will see

- **"Spent" stat in StatLine and Today/This Month cards**: may DECREASE for users with paid-from-goal expenses (those are now correctly excluded). This is a correction, not a regression.
- **Savings bucket**: will INCREASE for users with goal contributions or savings-account inbound transfers (previously underreported as zero).
- **Other buckets unchanged** — Needs/Wants math was already correct.
