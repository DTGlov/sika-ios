### Service
- `Services/DecisionService.swift` (`final class`, `SupabaseManager.shared.client`)
  - `ask(_:)` async throws → `AskDecisionResponse`. POST `/api/decisions/ask` with `Authorization: Bearer <jwt>` from `client.auth.currentSession?.accessToken`. 30s timeout (LLM calls can take 5–10s).
  - `recordOutcome(decisionId:outcome:)` async (no throws). POST `/api/decisions/outcome` with same Bearer auth. 10s timeout. Best-effort: errors are swallowed (matches web's silent fail at decision-sheet.tsx:89-105).
  - `DecisionError` enum (`invalidResponse`, `serverError(status:)`, `decodeFailed`, `noSession`).
  - `currentAccessToken()` is synchronous (`AuthClient.currentSession` is a sync property) — no `try await` needed.

### State
- `Features/Home/Components/DecisionSheet/DecisionSheetViewModel.swift`
  - `@Observable @MainActor final class` with 4-phase enum `Phase: Equatable` (`input` / `loading` / `result` / `error(message:)`)
  - `Phase.isResult` computed bool (avoids `==` on associated-value enum cases at the view layer; mirror of audit's "better pattern" suggestion)
  - Form state: `itemName`, `amountText`, `bucket` (default `.wants`), `urgency` (optional, default nil)
  - Result state: `decisionId`, `decision`

  - `toggleUrgency(_:)` — tapping selected option deselects (matches web)
  - `ask()` async — input → loading → result/error
  - `retry()` — error → input
  - `resolve(outcome:)` async → Bool — fires best-effort outcome; returns `true` for `.bought` so caller can switch tabs

## Locked architectural decisions

- **HTTP-only iOS client**: no Anthropic SDK, no API key in the iOS bundle.
- **Server-side compute**: web's existing `/api/decisions/ask` endpoint handles auth verification, `computeDecisionContext`, the Anthropic call, and the `purchase_decisions` insert. iOS sends 4 fields and renders the JSON response.
- **Bearer auth via Supabase Swift session**: `client.auth.currentSession?.accessToken` (sync property) on every request. Web's bearer-auth fallback shipped earlier today.
- **Base URL hardcoded**: `https://sika-dlrl.vercel.app`. Could be plumbed via `Bundle.infoDictionary` if test/staging deploys are added; not worth the abstraction yet.
- **Server-authoritative accent**: result pill color is `decision.accent` (one of green/amber/red/blue) — NOT derived from verdict. The LLM picks accent + verdict independently.
- **Outcome recording is best-effort**: errors are swallowed silently to match web's behavior. The user-facing flow never blocks on it.
- **Sheet detents**: `[.medium, .large]` with drag indicator visible — pure SwiftUI, no UIKit.
- **`@Observable @MainActor`** for the view model (iOS 17+; deployment target is 17.6).
- **Tab-switch via injected closure**, not AppState: `AuthenticatedRootView` owns `@State selectedTab`; threading `onSwitchToTransactions: () -> Void` through Home keeps AppState decoupled from navigation.
- **Auto-focus delay 100ms** matches web's `setTimeout(focus, 100)` — gives the sheet animation time to settle before the keyboard appears.
- **canSubmit gate**: `itemName` non-empty + `amount > 0`. Urgency is NOT required (matches web).
- **Urgency toggle**: tapping the active option deselects (sets to nil).
- **Verdict-line typography**: bold, foreground color (NOT accent — accent is reserved for icon + enum-label tracking).
- **No re-validation of LLM output on iOS**: server validates the 12-word verdict_line; iOS trusts JSONDecoder + DecisionData.Codable.

## Adaptations from the prompt's templates

The prompt's blueprint mostly fit, with these adaptations:

1. **`actor DecisionService { static let shared = ... }`** → `final class` + `SupabaseManager.shared.client` to match the existing iOS service pattern (Phases 2–7 precedent).
2. **`SupabaseClient.shared.client`** in the prompt → actual iOS pattern is `SupabaseManager.shared.client`. Verified via `grep` against `Sika/Core/Supabase/SupabaseClient.swift` and the other Phase services.
3. **`try await supabaseClient.auth.session`** → actual SDK API is `auth.currentSession` (synchronous property returning `Session?`). Removed `await`/`async` from `currentAccessToken()`.
4. **Hex literals on inline `Color(hex:)`** → the existing `SikaTheme.Color` tokens already cover gold (`sikaAccent`), gold-foreground (`primaryForeground`), rose (`sikaDanger`). Used those for theme stability. Kept inline `Color(hex:)` for the 4 accent palettes (green/amber/red/blue) since those are decision-domain-specific, not generic theme tokens, and for the bucket colors on `PurchaseDecisionBucket` to keep the model file SwiftUI-self-contained without coupling to the theme namespace.
5. **`Phase: Equatable` `==` check at view layer** → the prompt suggested computed `var isResult: Bool` as the safer alternative; took that — it sidesteps any synthesis subtleties and reads more clearly anyway.
6. **`Bundle.infoDictionary` for base URL** → not abstracted; single hardcoded URL with a comment pointing at the future option.
7. **iOS notes' `@Bindable var viewModel: DecisionSheetViewModel`** in InputView is correct for `@Observable`; kept it.
8. **Tab navigation** → audit allowed for "no-op if Sika's tab navigation pattern can't accommodate." Sika does have `selectedTab: MainTab` in `AuthenticatedRootView`, so `onSwitchToTransactions: { selectedTab = .transactions }` ships now (not deferred).

## Behavioral notes

- **Tap "Should I buy it?"** → sheet animates up at `.medium` detent.
- **100ms after sheet appears** → item-name field focuses and keyboard slides in.
- **Tap a bucket** → border + tinted background snap to that bucket's brand color (green/amber/blue).
- **Tap an urgency** → tints green when set; tap again to clear.
- **Tap "Let Sika decide"** → loading phase replaces input form (gold ring spins for 5–10s).
- **Result phase replaces loading** → header switches to "Here's the read"; verdict banner uses `decision.accent` (server-determined); math card shows bucket %, optional goal, optional alternatively-line; sika-says card preserves multi-paragraph reasoning.
- **"Nah, skip"** → fires `recordOutcome(.skipped)` (silent), dismisses the sheet.
- **"I bought it"** → fires `recordOutcome(.bought)` (silent), dismisses the sheet, then the closure switches the main tab to Transactions.
- **Error phase** → "Failed to get decision. Try again." with a "Try again" button that resets to `input`. Form values are preserved.
- **Network failure mid-flight** → caught at the catch block in `viewModel.ask()`, transitions to error phase. Same path covers HTTP non-2xx, decode failures, or Supabase session loss.
