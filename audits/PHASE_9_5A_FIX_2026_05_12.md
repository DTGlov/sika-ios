Phase 9 MVP shipped the HealthRow on Home with a trailing chevron whose
tap was a no-op (the file even said so: "Phase 9.5 wires /health
detail"). This phase ships that destination: a NavigationStack push
from HealthRow into `HealthDetailView`, showing the score hero, stat
tiles, factor breakdown with expandable per-factor copy, and a
how-this-works footer. Read-only — no mutations.

## What Shipped

### Views (Features/Health/)
- `HealthDetailView.swift` (new) — full detail page composed of:
  - **Score hero**: 72pt count-up from 0 → current over ~1.2s, label
    chip ("Excellent" / "Good" / "Fair" / "Needs attention" /
    "Critical") in the label's color, and "Out of 100" caption.
    Wrapped in a 20pt-radius card with a 2pt label-tinted stroke.
  - **Stat tiles row** (4 compact tiles): logging streak days,
    savings streak weeks, momentum total points, badges
    unlocked/total. Single line; `minimumScaleFactor` to absorb
    long values without truncation.
  - **Factor breakdown**: 5 `FactorCardView`s in audit order
    (emergency coverage → budget discipline → consistency → goal
    commitment → diversification). Staggered entry 100ms apart.
  - **How-this-works footer**: muted-background card with explainer
    copy about score updates.
- `Components/FactorCardView.swift` (new) — per-factor card with:
  - Header row: factor name + weight%, score (large, color-coded)
  - Animated progress bar (0 → score% over 800ms with 150ms delay)
  - "Learn more" expander that surfaces the calculator-provided
    `description` ("WHAT THIS MEANS") and `tip` ("TO IMPROVE")
  - Color thresholds: ≥70 green, 40–69 yellow, <40 red

### Home wiring (Features/Home/AuthenticatedHomeView.swift)

  the row itself stays presentational; the parent owns the tap.
- New `.navigationDestination(isPresented: $showHealthDetail) { HealthDetailView() }`

### NOT shipped (intentional)

**No `HealthFactor` extension with `displayName` / `explainerCopy` /
`improvementSuggestion`.** The model already exposes `name` (from
`HealthFactorId.displayName`), `description` (a contextual string
computed by `HealthScoreCalculator` per factor — e.g. "Your Life
Savings covers 2.4 months of Needs."), and `tip` (e.g. "Build Life
Savings to cover 3 months (~GHS 12,000)"). Adding static extension
copy would diverge from the live data the calculator produces.

## Locked architectural decisions

- **NavigationStack push, not sheet.** Reuses Home's existing
  `NavigationStack` (already established for MonthlyRecap / Digest /
  Cycle detail). Standard iOS back chevron + edge swipe to return.
- **Read-only view.** No CRUD, no edits, no settings adjustments.
  Suggestions are static text — not yet wired to programmatic
  deep-links to Goals / Recurring / Settings (deferred to 9.5b).
- **Hero count-up animation** uses a step-based `DispatchQueue`
  scheduler (one tick per score increment, time interval =
  `1.2s / target`). Linear-ish, lands on the exact final number.
  Deterministic and cheap.
- **Factor staggering**: 100ms apart, spring animation
  (response 0.5, damping 0.7). Each card sets its own progress bar
  to animate after becoming visible.
- **Single live source**: `appState.healthSnapshot.score`. The
  detail view never recomputes; the score, label, and factors all
  come from Phase 9's `HealthService` + `HealthScoreCalculator`.
- **Empty/missing state**: when `healthSnapshot == nil` or the
  score is `nil`, the hero shows `0`, the label shows `—` in
  muted gray, factor breakdown shows a friendly empty-state card.
  No crashes on first-launch / pre-data state.

## Adaptations from the prompt's blueprint

1. **Tier system is 5-label, not 3-tier.** The prompt described
   Bronze (0–49) / Silver (50–79) / Gold (80–100). The actual iOS
   model is 5 labels (`HealthLabel`): excellent (80+), good (60–79),
   fair (40–59), needsAttention (20–39), critical (<20) — each with
   its own color via `HealthLabel.color`. Hero + chip use this
   model directly, not a Bronze/Silver/Gold remap.
2. **Factor IDs differ from prompt.** Actual IDs are
   `emergency_coverage`, `budget_discipline`, `consistency`,
   `goal_commitment`, `diversification` (not the prompt's
   `savings_rate`, `spending_under_budget`, `goal_commitment`,
   `emergency_coverage`, `recurring_discipline`). The detail view
   reads `factor.name` from the model, so no hardcoded ID list
   leaks into the view.
3. **No `HealthFactor` extension.** Calculator already populates
   `description` (contextual; e.g. shows the specific months
   covered) and `tip` (contextual; e.g. includes the formatted
   GHS amount needed). Using the existing fields means the detail
   view reflects the user's actual state, not generic copy.
4. **`appState.healthSnapshot`, not `appState.healthScore`.**
   The model is composed (`HealthSnapshot` contains score + streaks
   + momentum + userBadges). Stat tiles read all four substructures
   from the same snapshot — no separate `loggingStreak` /
   `unlockedBadges` accessors needed on AppState.
5. **Stat tiles** show savings streak in weeks (`savings_current` is
   a weekly counter on iOS), badges as "N/8" (the catalog count is
   public via `BadgeCatalog.totalCount`), and momentum as raw
   points (not just tier name).
6. **iOS pattern is `@Observable` + `@Environment`.** The prompt's
   `@EnvironmentObject var appState: AppState` is replaced with
   `@Environment(AppState.self) private var appState` to match
   AppState's declaration shape.

## Behavioral notes

- **Count-up animation only on first appearance.** Re-pushing the
  detail page (via back → re-tap) resets `hasAppeared` because
  it's local @State on a view that unmounts on pop. Subsequent
  pushes replay the animation, matching the prompt's intent.
- **Progress bars animate independently per card.** Each
  `FactorCardView` watches its `isVisible` flag and triggers its
  own `animatedProgress` when it becomes visible. The 150ms delay
  inside each card prevents the bar fill from starting before the
  card's offset+opacity entrance completes.
- **HealthRow's chevron is now meaningful.** Previously decorative;
  now signals the tap affordance correctly.
- **No mutations fire from this view.** Tapping any card, the
  expander, or any stat tile does not write to Supabase.
