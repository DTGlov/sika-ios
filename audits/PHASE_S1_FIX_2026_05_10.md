# Phase S1 — Settings Shell + Theme/Currency/Budget/Danger — 2026-05-10

Implementer: Claude Code
Source-of-truth audit: `/audits/SETTINGS_TAB_2026_05_10.md` (web — not present in iOS repo at PR time; the prompt's inline spec served as the working blueprint)

Phase 6 shipped a partial Settings shell (heritage card themes only). This phase rebuilds Settings into a comprehensive sheet covering Appearance, Currency, Haptics, Notifications, Income Sources (read-only), Card Style, Total Income echo + Budget Month + Budget Split, Categories (read-only), App preferences (Reset hints), Sign out, Danger zone (typed-DELETE), and Privacy policy link.

Income Sources CRUD ships in **S2**. Categories CRUD ships in **S3**.

## What Shipped

### Models
- `Models/SystemTheme.swift` (new) — `SystemTheme` enum with `displayName`, `systemImage`, `uiUserInterfaceStyle` bridge, plus a `Profile.themePreferenceValue` typed accessor. Defends against legacy "system" rows by falling back to `.light`.
- `Models/Profile.swift` — added `withThemePreference`, `withHapticsEnabled`, `withCurrency`, `withBudgetConfig` mutators (plus a private `copy(...)` helper). Existing `withCardTheme` continues to work via the same helper.

### Service
- `Services/ProfileService.swift` — extended the existing struct with:
  - HTTP/Bearer mutations: `updateTheme(_:)`, `updateHaptics(_:)`, `updateCurrency(_:)`, `deleteAccount()`
  - Direct Supabase: `updateBudgetConfig(userId:cycleStartDay:needsPercent:wantsPercent:savingsPercent:)`
  - Private helpers: `patchJSON(path:body:)`, `sendDelete(path:)`, `validate(response:data:path:)`, `currentAccessToken()`
  - Hardcoded base URL `https://sika-dlrl.vercel.app` matching Phase 8's `DecisionService` precedent.
- `ProfileServiceError` extended with `requestFailed` and `serverError(status:)` cases.

### State (`AppState`)
Added (after the Recurring section):
- Computed `totalMonthlyIncomeComputed: Decimal` — sum of active income sources' `monthlyEquivalent`.
- `applySystemTheme(_:)` — applies a `SystemTheme` to the active `UIWindow` via `overrideUserInterfaceStyle`.
- 5 actions:
  - `updateSystemTheme(_:)` — optimistic + UIWindow apply + HTTP/Bearer persist + rollback on failure
  - `updateHapticsEnabled(_:)` — optimistic + HTTP/Bearer + rollback
  - `updateCurrency(_:)` — non-optimistic; awaits the round-trip and returns Bool
  - `saveBudgetConfig(...)` — non-optimistic; direct Supabase write
  - `deleteAccount()` — calls cascade endpoint, then signs out and resets local state

## Locked architectural decisions

- **Settings reached via gear icon on Home's TopBar (sheet presentation).** Phase 6 already wired this; S1 keeps the sheet pattern (the prompt allowed sheet OR push). NOT a 6th tab.
- **Light / Dark only.** No System/Auto option. 2-tile picker.
- **Theme persists locally (UIWindow override) AND remotely** (PATCH /api/profile/theme).
- **Currency picker is its own NavigationStack push.** Sheet wraps a NavigationStack so the push works.
- **Budget Month + Budget Split share a single Save button.** Disabled when sum != 100 or unchanged.
- **Income Sources is read-only.** Add/Edit/Trash icons render but are no-ops with "Coming soon" toasts. S2 wires CRUD.
- **Categories is read-only.** Same shape. S3 wires CRUD.
- **Card Style section reuses Phase 6's existing components verbatim.** No rebuild.
- **Delete account: typed DELETE** confirmation Alert. Calls /api/profile/delete via Bearer auth. On success: signs out and routes to login. On failure: secondary Alert with email contact.
- **Reset onboarding hints**: confirmation Alert before deleting (web has no confirm; iOS adds one for idiomatic safety).
- **Sign out: no confirmation** (matches web; sign-out is reversible).
- **Privacy policy: `SFSafariViewController`** loading the canonical URL (TODO to confirm exact host).
- **4 mutations bundled as Profile API calls**: theme / haptics / currency / delete via HTTP/Bearer.
- **Budget Month + Budget Split saves directly to Supabase** (RLS-scoped; no API route).
- **NO mutation hooks anywhere** (configuration is not user action that earns points/streaks/badges).
- **NO 6th tab**. iOS has 5 tabs forever.

## Adaptations from the prompt's blueprint

1. **`@Published` AppState → `@Observable`** with `private(set) var` (Phase precedent).
2. **`Profile.email` doesn't exist on iOS** — Profile model omits email per docstring; email lives on `auth.users`. None of the S1 sections actually display email, so this is a no-op for the spec.
3. **Profile fields are `Decimal`, not `Int`/`Double`** — `needsPercent`, `wantsPercent`, `savingsPercent`, `monthlyIncome` all `Decimal?`. `BudgetConfigForm` uses `Int` state for the Stepper UI and bridges to `Decimal` at the AppState boundary.
4. **`Profile.cycleStartDay: Int?`** (not `Int`) — defaults to 1 in the form.
5. **`Profile.themePreference` is `String`** (NOT NULL on DB), not an enum — added `themePreferenceValue: SystemTheme` typed accessor to bridge.
6. **Profile mutators**: existing `withCardTheme` worked via direct memberwise init; I refactored it to share a private `copy(...)` helper with the four new mutators (theme / haptics / currency / budgetConfig).
7. **`SupabaseClient.shared.auth.session`** in the prompt is wrong for iOS. iOS pattern is `SupabaseManager.shared.client.auth.currentSession?.accessToken`. ProfileService follows the existing `DecisionService` precedent.
8. **Base URL is `https://sika-dlrl.vercel.app`** (Phase 8 precedent), not `https://sika.app`. Documented for Privacy URL too.
9. **iOS already has `Currency` + `CurrencyCatalog.filtered(by:)`** — skipped the re-port. Existing catalog has 128 entries (TWD-deduped vs web's 131; matches iOS's existing model file's docstring).
10. **`AppState.signOut()` and `AppState.resetHints()` already exist** — reused them; no new methods.
11. **Settings is presented as `.sheet`** (Phase 6), not `NavigationLink`-pushed. Wrapped the sheet content in `NavigationStack` for Currency sub-route push.
12. **`UIKit` import** required in `SystemTheme.swift` for `UIUserInterfaceStyle` bridge and in `NotificationSettings.swift` for `UIApplication.openSettingsURLString`.
13. **iOS Alert TextField** doesn't accept `.textInputAutocapitalization(.characters)` — removed; the alert title text is enough cue for users to type uppercase.

## Behavioral notes

- **Theme toggle**: optimistic — flips Profile, applies UIWindow style, fires HTTP. On failure, rolls back both the Profile state and the UIWindow style.
- **Currency**: non-optimistic — Save commits via HTTP, success toast + dismiss; failure toast keeps the picker open.
- **Notifications toggle**: only affects iOS-level permission state. Enable when `notDetermined` triggers `requestAuthorization` + `registerForRemoteNotifications`. Enable when `denied` shows the Open-Settings alert. Disable is a no-op at the app level (users disable in iOS Settings).
- **Budget Save**: validation prevents save unless sum == 100 AND fields differ from profile.
- **Reset hints**: confirmation Alert → `appState.resetHints()` (existing). Toast on success/failure.
- **Sign out**: routes back to `flow = .signIn`. The sheet auto-dismisses via the auth flow change; explicit `dismiss()` is a belt-and-braces.
- **Account deletion**: typed DELETE → cascade endpoint → success signs out + drops to login; failure shows secondary email-contact alert.

## Web prerequisite

Per the prompt: web PR `feat/bearer-auth-profile` adds Bearer auth fallback to `/api/profile/{theme,haptics,currency,delete}` routes. **If that PR is not merged**, the four HTTP mutations (theme / haptics / currency / delete) will return 401. The build is green either way; the runtime behavior depends on the web prereq.
