## Locked architectural decisions

- **Soft delete (`archived = true`)**, NOT hard delete. Categories MUST
  soft-archive because transactions reference them historically.
  Asymmetric to S2's hard delete on income sources (which are config-only
  and don't have FK consumers).
- **Restore UI exists** for categories. No confirmation on restore
  (reversible — the user can always archive again).
- **Archive confirmation Alert exists** on iOS (web has none; idiomatic
  divergence — taking a row out of pickers feels destructive enough
  to warrant a Cancel button).
- **Bucket-coupling**: `type = .expense` → bucket can be Needs / Wants
  / Savings / None (null). `type = .income` or `.adjustment` →
  `bucketId` forced to nil; the bucket picker hides entirely. Enforced
  at both the chip-handler and submit-handler layers.
- **6 + 1 render groups**: NEEDS / WANTS / SAVINGS / SPENDING (NO
  BUCKET) / INCOME / ADJUSTMENTS + Archived collapsible.
- **23-emoji catalog**, ported verbatim from audit Section 11.5.
- **Top-level "+ Add" button** (gold accent), NOT per-section. The
  modal lets the user pick type first, then bucket if expense.
- **Entire row tappable for edit** (not per-icon pencil). The archive
  icon is the only "active" affordance on the row.
- **Form is bottom sheet** (`.presentationDetents([.large])`), iOS
  idiom — NOT centered Dialog like web.
- **NO mutation hooks**. Configuration paths don't tick points /
  streaks / badges — same rule as S1/S2.

## Adaptations from the prompt's blueprint

1. **DB column names: `category_type` and `archived`** (not `type` and
   `is_archived`). iOS S1 already shipped with these column names
   working in production; the prompt's mapping reflects web's
   convention but the actual `categories` table on Supabase uses the
   iOS variants. Confirmed against S1's working filter call:
   `.eq("category_type", value: ...)`.
2. **Single `categories` array on AppState**, not a separate
   `allCategoriesIncludingArchived`. Existing iOS code already fetches
   the full set on bootstrap and filters at the view boundary. Adding
   a second array would have:
   - Doubled memory for the same data
   - Required updating 6+ call sites in Home / Transactions /
     Recurring to switch between the two arrays
   - Diverged from the established AppState pattern (one observable
     truth per resource)
   Mutation methods update the single array; archive sets
   `archived = true` in place, restore sets `archived = false`.
3. **iOS doesn't add `BudgetBucketName` enum** — the existing
   `BudgetBucket` model stores `name` as a lowercase string ("needs",
   "wants", "savings"). The form sheet looks up the right bucket via
   `bucketByName[nameKey]` rather than enum dispatch. Matches the
   pattern S1's CategoriesSection already established.
4. **iOS doesn't join `budget_buckets(*)` in the select** — bucket
   resolution happens client-side via `appState.budgetBuckets` (which
   bootstrap loads once). Keeps the create/update round-trip narrow
   and matches the read-time pattern.
5. **No `mutationCount` increment** — iOS AppState doesn't have a
   `mutationCount` field (web's gamification counter). S1/S2 already
   noted this divergence; S3 follows suit.
6. **Cross-tab isolation already correct** — pre-S3 surfaces already
   filtered `archived != true` at the picker boundary:
   - `TransactionFilterSheet.swift:94`
   - `RecurringFormSheet.swift:133`
   Surfaces that need historical category names (BucketSpendCalculator,
   RecentTransactionsWidget, CycleDetailView) intentionally include
   archived so old transactions still resolve their category name.
   No changes needed.

## Behavioral notes

- **Create**: defaults to `type = .expense`, `bucketId = nil`,
  `icon = "🏷️"`, `archived = false` (forced).
- **Edit**: pre-fills from `editingCategory` on `.onAppear`. Switching
  type from .expense to .income or .adjustment in edit mode clears
  bucketId. Switching back to .expense leaves bucketId nil — the user
  picks again.
- **Archive**: tap archive icon → Alert → confirm → AppState writes
  `archived = true` on Supabase + flips local row. Toast confirms
  success.
- **Restore**: direct (no confirmation) → AppState writes `archived =
  false` on Supabase + flips local row. Toast confirms.
- **Archived collapsible**: collapsed by default, shows the row count
  in the header label. Tapping the header animates the expansion.
  Archived rows render at 50% opacity with strikethrough name + gold
  Restore pill.
- **Refresh on Settings open**: SettingsView's `.task` re-fetches
  `categories` so multi-device archive state stays in sync. Cheap
  single-table query.

## Asymmetry with S2 (intentional)

| Aspect | S2 Income Sources | S3 Categories |
|---|---|---|
| Delete semantics | Hard delete | Soft archive |
| Restore UI | None | Yes |
| Confirmation | Yes (Alert) | Yes (Alert) for archive; none for restore |
| FK consumers | None | Transactions reference category_id |
| Visibility after archive | N/A | Hidden in pickers, shown in Settings |

The asymmetry is driven by the FK relationship: categories MUST soft-
archive because historical transactions still reference their id;
income sources can hard-delete because they're configuration-only.
